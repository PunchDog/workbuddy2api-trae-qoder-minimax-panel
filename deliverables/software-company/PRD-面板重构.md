## 原始需求复述

1. 重构前端页面显示，参考 <https://github.com/cclank/tokei> 的设计。
2. 前端重构主体改为使用 tdesign、wails v3。

> 已拍板约束（不推翻）：交付为 Wails v3 桌面应用而非纯浏览器面板；前端用 Vue3 + tdesign-vue-next + Vite；API 沿用 `/panel/api/*`；网关与 8 视图功能不丢失。

---

## 1. 产品目标

**一句话**：把现役「原生 HTML 面板」升级为「tokei 风格卡片化、Vue3+tdesign 组件化、Wails v3 承载」的桌面仪表盘，让用户在一个高信息密度的窗口里一眼掌控多账号合集的签到、用量、积分与网关状态。

- **目标一｜一眼可读**：借鉴 tokei 的工具卡片语言，把 8 个视图的关键观测值前置为卡片网格，用户开窗 3 秒内掌握全局健康度（签到状态、额度水位、今日用量、异常数）。
- **目标二｜可维护可演进**：用 Vue3 + tdesign-vue-next + Vite 替换 6552 行原生 JS 与内联 CSS，建立组件化结构与构建链，结束"单文件巨型脚本"的技术债。
- **目标三｜桌面一等体验**：以 Wails v3 桌面壳承载面板（系统窗口、托盘、本地资源），同时保持网关后台运行与 API 契约不变，做到"改造显示不动后端"。

---

## 2. 用户故事

1. 作为**多账号运营者**，我希望打开桌面应用就看到按平台（WorkBuddy/Trae/Qoder/MiniMax/豆包/OpenCode）分组的状态卡片和额度水位，以便快速判断今天该给哪些账号签到、哪些额度即将耗尽。
2. 作为**日常使用者**，我希望在一个统一窗口里切换签到池、用量、积分构成、任务中心等视图，且风格与卡片语言一致，以便不用在不同页面间重新适应交互。
3. 作为**注重观感的用户**，我希望桌面应用有明暗双主题并跟随系统、本地记忆，数值等宽对齐、状态色语义一致，以便在长时间盯盘时视觉舒适、读数可靠。
4. 作为**配置管理员**，我希望在桌面面板里完成账号增删改（6 tab）、访问密钥、Qoder 设备/出口、配置开关等操作，且功能与旧版一一对应，以便迁移后无需回退浏览器面板。
5. 作为**排障者**，我希望在运行日志视图按时间/维度筛选请求记录并看到客户端/IP 等标注，以便定位某次调用来自哪个上游、是否异常。

## 4. UI 设计稿

### 4.1 设计语言取舍

tokei README 未提供具体色值/字体规范，其可迁移的是**信息设计语言**：工具卡片化、glanceable 高信息密度、短标签+数值+状态、渐进式展开、时间维度切换、数据透明标注。而**具体配色沿用现役靛蓝冷石墨令牌**（已验证、语义清晰、明暗双主题成熟），不照搬 tokei 的菜单栏白色/彩色样式——因为我们交付的是桌面窗口仪表盘，不是 macOS 菜单栏应用。

**取舍结论**：**结构学 tokei（卡片化 + 信息密度 + 展开层级），皮肤继承现役（靛蓝 #5b7cfa + 冷石墨 + 语义状态色）**，tdesign 组件在此令牌体系下做主题定制。

### 4.2 配色令牌建议（沿用现役，映射为 tdesign 主题变量）

| 语义令牌 | 暗色（默认） | 亮色 | 用途 |
| --- | --- | --- | --- |
| `--bg` / 页面底 | `#0c0e14` | `#f4f5f8` | 应用背景 |
| `--surface` / 卡片面 | `#14171f` | `#ffffff` | 卡片/面板底 |
| `--surface-2` / 抬升 | `#1a1e28` | `#f8f9fb` | 次级容器、表头 |
| `--line` / 描边 | `#262c3a` | `#e2e5ec` | 分隔线、卡片边框 |
| `--ink` / 主文 | `#e8ebf2` | `#14171f` | 数值、标题 |
| `--ink-2/3` / 次文 | `#a8b0c2` / `#6b7488` | `#545c6e` / `#8b93a5` | 标签、辅助 |
| `--accent` / 强调 | `#5b7cfa` | `#3d5fe0` | 主按钮、选中态、激活轨 |
| `--ok` / 正常 | `#3ddc97` | `#0f9d63` | 签到成功、额度充足 |
| `--warn` / 提醒 | `#f5b544` | `#b47611` | 额度偏低、待处理 |
| `--bad` / 异常 | `#f0655f` | `#cf3b34` | 失败、过期、需干预 |

- 数值统一 `tabular-nums`；KPI 卡左侧 `3px` 语义色轨；状态点/徽标按 ok/warn/bad 三态。
- tdesign 通过 `ConfigProvider` + 自定义 CSS 变量接入上述令牌，保证 Table/Dialog/Form/Select 与整体冷石墨风格一致。

### 4.4 八个视图的卡片化信息架构

| 视图 | 卡片化落地 | 关键观测值 / 主要组件 |
| --- | --- | --- |
| **签到池**（默认首页） | 顶部 KPI 卡（今日签到、账号健康、额度水位、待办异常）+ 按平台分组的工具卡片网格，卡片内展示签到状态、积分增量、额度、到期时间 | 状态徽标、进度环/条、平台卡、一键签到按钮、展开明细 |
| **用量** | KPI 卡（今日 Tokens、成本估算、缓存命中、请求数）+ 时间维度切换 + 分组卡片（OpenCode 订阅配额 / 官方用量 / Qoder 直连额度 / 网关用量）+ 用量明细表 | 折线图、占比条、维度切换（按账号/模型/域）、明细表（tabular-nums） |
| **积分构成** | 平台卡（Trae/Qoder 积分包）+ 到期时间聚合条 + 明细表 | 最早到期优先、未用完包聚合、进度条 |
| **任务中心** | 任务卡网格（状态 + 进度 dot）+ 积分任务弹窗入口 | 任务进度点（done/run/err）、执行按钮、状态标签 |
| **IDE 账号池** | 账号卡网格（每账号一张：状态、额度、绑定信息）+ 筛选栏 + 添加账号入口（6 tab Dialog） | 账号卡、状态轨、表单 Dialog（WorkBuddy/Trae/Qoder/MiniMax/豆包/导入JSON） |
| **模型与档位** | 档位分组卡 + 模型表（可展开行：输入/输出/缓存/单价） | 筛选栏、模型明细展开、档位标签 |
| **配置** | 分区设置卡（网关、鉴权、OpenCode、运行日志 IP/客户端开关等），每区一张卡 + 保存操作 | TDesign Form/Switch/Input、分区 Card、即时生效提示 |
| **运行日志** | 顶部 KPI（今日请求、错误率、平均延迟）+ 筛选栏（时间/维度）+ 请求记录表（最多 1000 条，限高滚动）+ 客户端/IP 标注 | 表格、筛选栏、状态标签、行数提示 |

### 4.5 关键组件清单（基于 tdesign-vue-next）

- **布局类**：`TLayout`/`TMenu`（左侧导航）、`THeader`（顶栏）、卡片容器（自定义 `.panel-card`，带语义色轨）。
- **展示类**：`TStatistic`/自定义 KPI 卡、`TTag`（状态/档位/来源）、`TProgress`（额度水位）、`TTable`（明细/日志，等宽数值）、`TTooltip`（数据透明标注）。
- **交互类**：`TDialog`（添加账号 6 tab、积分任务、Qoder 设备/出口、领取历史、券码、访问密钥、构建失配提示）、`TForm`/`TInput`/`TSelect`/`TSwitch`（配置）、`TDatePicker`（时间范围）、`TTabs`（视图内维度切换）、`TLoading`/`TMessage`（刷新反馈）。
- **通用**：`ConfigProvider` 主题令牌、图标（沿用内联 SVG stroke=currentColor 或 tdesign-icon）、明暗主题 composable（跟随系统 + localStorage）。

## 5. 范围边界

- **改显示不改后端 API 契约**：所有数据交互仍走 `/panel/api/*`，端点路径、请求/响应字段、Bearer 鉴权逻辑一律不变；后端 Go 网关代码原则上不改（除 Wails 桌面壳接入所需的最小入口层）。
- **原 8 视图与功能不丢失**：签到池、用量、积分构成、任务中心、IDE 账号池、模型与档位、配置、运行日志及全部弹窗/筛选/刷新交互逐一等价迁移；这是替换旧面板的验收底线。
- **形态变更已定**：交付为 Wails v3 桌面应用；是否**额外保留**浏览器访问方式列为待确认（见 §6），默认网关 API 仍可被 HTTP 访问，但"管理面板 UI"以桌面应用为主。
- **不做**：后端业务逻辑重构、数据库迁移、新增账号平台类型、Wails 架构设计（由架构师负责）、具体代码实现。
- **数据一致性**：tokei 的成本估算/热力图等图表若后端无对应数据支撑，则降级为 P2 或标注"估算参照"，不得虚构读数。

## 6. 待确认问题

1. **是否保留浏览器访问方式**：桌面应用为主，是否仍需 `http://host:7863/panel` 保留一份可用的 Web 面板？（影响是否维护双份 UI 或采用 Wails 服务器构建模式）
2. **桌面窗口初始尺寸与行为**：默认窗口大小（如 1280×800？）、是否支持关闭到托盘、是否开机自启、是否记住窗口位置。
3. **是否启用 Wails 服务器构建模式**：同一应用无窗口以 HTTP server 运行，作为"保留浏览器访问"的候选方案，需架构评估成本。
4. **tokei 增强图表的取舍**：成本折线图/周热力图/工具占比（R-12）是否首版纳入？若纳入，后端是否已有可支撑的历史时序数据？
5. **tdesign 组件库版本与主题深度**：使用 `tdesign-vue-next` 最新版并做深色主题定制，是否接受其默认视觉与现役冷石墨的融合方案，还是要求高度还原现役令牌？
6. **默认主题**：暗色为默认（现役跟随系统），是否维持"跟随系统优先、localStorage 记忆"策略？
7. **数据透明度标注强度**：额度/成本估算的"估算参照/读数时间/数据来源"标注做到何种程度（借鉴 tokei 的谨慎标注）。
